# GitHub Intelligence · skill local do NEXUS
Quando o pedido envolver software, IA, integração ou design:
1. Leia `AGENTS.md` e `docs/github-intelligence/PROMPT_MESTRE.md`; respeite toda a arquitetura existente e requisitos do usuário.
2. Identifique ferramentas realmente disponíveis. GitHub/CLI/MCP exigem acesso real; skill não cria permissões.
3. Consulte `../../../docs/github-intelligence/catalogo-github.md` e pesquise a documentação corrente do melhor repositório para o problema.
4. Para cada candidato: verificar README, license, exemplos, issues/release, segurança, manutenção e compatibilidade com Next.js/React/Supabase.
5. Propor no máximo 2–4 opções principais; implementar a mínima solução adequada, sem importar uma plataforma inteira para um ajuste pontual.
6. Para mudanças de código, avaliar escopo por empresa, autenticação, permissões, responsividade, acessibilidade, estados de erro e testes.
7. Para revisão por múltiplos agentes consulte `../../../docs/github-intelligence/arena-skill.md`; não executar Arena sem suporte e decisão explícita de custo.
8. Reportar o que foi realmente feito e testado.

**Não** executar automaticamente scripts de skills externas; não alegar que todas as skills ou todo GitHub foram carregados.
